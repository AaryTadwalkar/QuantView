## 0. Tier 1 Authority & Governance Rule (`ADR-007`)

1. **Tier 1 Authority Condition:** An Architecture Decision Record in this register carries **Tier 1 Authority** if and only if its status is **`OWNER_APPROVED`**. Once marked `OWNER_APPROVED`, no lower-tier document (`Tier 2` HLD, `Tier 3` LLD, `Tier 4` UI/Report Specifications, or Cross-Cutting Control Documents) and no coding agent may silently reverse, weaken, or bypass the decision without a new owner-approved superseding ADR.
2. **Non-Approved Statuses:**
   - **`PROPOSED` (`ADR-016`):** Designates an architectural rule whose structure is defined in the baseline, but whose concrete numeric threshold (`Mode S` synthetic-option calibration hurdle) must be pre-registered by the owner before running that experiment.
   - **`DEFERRED` (`ADR-039`):** Designates a capability (`LIMIT` order fill semantics, `CAP-21`, `T7.16`) that is intentionally excluded from v1 implementation (`v1` manual and strategy orders are `MARKET`-only per `ADR-028`) and retained solely as a post-v1 specification.
3. **1-to-1 Canonical Numbering (`ADR-001`–`ADR-041`):** This register uses the canonical Person 2 / Final HLD (`§16`) numbering (`ADR-001` through `ADR-041`). Where Person 1's historical drafts (`DOCS/person_1/`) used a different ADR number for the same concept, the `"Historical P1 Cross-Ref"` column records that mapping so engineers inspecting archived logs never confuse numbering schemes.
